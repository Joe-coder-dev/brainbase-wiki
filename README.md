# BrainBase Wiki

The public wiki at **[wiki.brainbase.no](https://wiki.brainbase.no)** — guides for BrainBase
consultants covering contracts, accounting, benefits, meetups and how to contribute to the network.

Built with [Docusaurus 2](https://docusaurus.io/), a static site generator: the Markdown in `docs/`
is compiled into plain HTML/JS and served as static files.

## Getting started

Requires Node.js 16.14 or newer (Docusaurus's floor); builds fine on current Node.

```bash
npm ci      # NOT `npm install` — see "Dependencies" below
npm start   # dev server on http://localhost:3000, with live reload
```

## Writing content

Docs live in `docs/`, split into the sections that appear in the navbar:

| Folder | Navbar label |
| --- | --- |
| `docs/consultant-wiki/` | Konsulentwiki |
| `docs/network-contributions/` | Bidra i nettverket |
| `docs/meetups/` | Meetups |

The sidebar is **autogenerated from the folder structure** (`sidebars.js`), so adding a Markdown
file is enough to make it appear. Ordering and section titles come from the `_category_.json` file
in each folder. Blog posts live in `blog/`, images in `static/img/`.

Every page needs frontmatter:

```markdown
---
id: faq
title: F.A.Q
description: Vanlige spørsmål om plattformen brainbase.no.
---
```

Most content is written in Norwegian. Docusaurus
[admonitions](https://docusaurus.io/docs/2.x/markdown-features/admonitions) (`:::tip`,
`:::caution`, `:::info`) are used throughout.

> **Heading anchors are a public API.** Deep links into this wiki are embedded in the BrainBase
> platform and in automated emails to consultants — for example the "contract ending today" reminder
> links to `internal-and-technical/faq#jeg-har-en-kontraktsfornyelse-...`. Docusaurus derives anchor
> ids from heading text, so **rewording a heading silently breaks those links**. Pin the anchor with
> an explicit id when a heading is linked from outside:
>
> ```markdown
> ### Some heading {#the-original-anchor-id}
> ```

## Deployment

Hosted on **Netlify**. Merging to `main` triggers a build and publishes automatically — there is
nothing to run by hand.

- **Production:** <https://wiki.brainbase.no> (custom domain)
- **Netlify subdomain:** <https://brainbase-wiki.netlify.app> (same site, also publicly reachable)
- Pull requests get a Netlify deploy preview, if previews are enabled on the site.

Build settings (build command and the `build/` publish directory) are configured **in the Netlify
UI**, not in this repo — there is no `netlify.toml` and no GitHub Actions workflow. If you need to
change how the site builds, that is where to look.

To reproduce a production build locally:

```bash
npm run build   # outputs to build/
npm run serve   # serves build/ at http://localhost:3000
```

Note that `npm run build` fails on broken internal links (`onBrokenLinks: 'throw'`), so a bad link
will break the deploy rather than ship silently.

## Dependencies

**Always install with `npm ci`, never `npm install`.** The site pulls in
`@cmfcmf/docusaurus-search-local` (which prebuilds the offline search index), and that plugin
depends on `cheerio` via the range `^1.0.0-rc.9`. That range floats up to cheerio `1.0.0` stable,
which removed the default export the plugin relies on — so a plain `npm install` can drift past the
lockfile and break the build with:

```
TypeError: Cannot read properties of undefined (reading 'load')
    at html2text (.../docusaurus-search-local/lib/server/parse.js)
```

`package-lock.json` pins the working version (`cheerio@1.0.0-rc.12`), and `npm ci` installs exactly
that. If you have already hit this, `rm -rf node_modules && npm ci` fixes it.

Docusaurus is on `2.0.0-beta.21` and is several major versions behind; upgrading is a known piece of
outstanding maintenance.
